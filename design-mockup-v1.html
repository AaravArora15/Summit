30 Premium paywall

Every free-tier limit is printed next to its Pro counterpart, so the offer reads as honest rather than extractive. Nothing about claiming, badges, serials, parties or safety is behind it — Pro sells search depth, history and cosmetics.

Free tier statedAnnual default7-day trialRestore in header

How this maps to RevenueCat

  • One entitlement, "pro". Every gate in the prototype reads a single boolean from CustomerInfo.entitlements.active["pro"]. No per-feature SKUs.
  • One offering, two packages. $rc_annual (default, pre-selected) and $rc_monthly. Prices, currency and the trial badge on screen 30 come from the fetched Offering rather than hardcoded strings, so a Singapore price renders in SGD without a build.
  • Four gated surfaces, marked in the mock: rarity and terrain filters (Explore), journal entries older than 30 days (Collection), the fourth-and-later mystery reveal each day (Home), and profile frames and featured slots (Profile). Each one shows the same gate sheet from screen 29.
  • Restore purchases appears twice, as required: in the paywall header and under Settings → Subscription.
  • Never gated: claiming a discovery, badge serials, safety and weather data, party membership, quest participation, seasonal territory. Locking any of those would turn a game into a toll road.
07

System spec

The rules the thirty screens above are built from, and what needs deciding before the clickable build starts.

Bottom navigation

  • Home · Collection · Explore · Party · Profile. Explore sits in the centre slot with a raised gold orb, because the brief calls for it to be visually dominant and slot three is the only position that can carry that. The brief's written order put Explore second; centring it is the one deliberate deviation.
  • Collection is labelled COLLECT in the tab bar — a verb, matching the four other tabs.
  • Tabs are hidden on every full-screen moment: arrival, reward reveal, collection complete, paywall, and the mystery checkpoint flow. The loop's dramatic beats own the whole display.
  • Badge counts never appear on the Collection tab. A red dot on Profile signals party and season activity only.

Screen flow

  • Onboarding 01 → 02 → 03 → 04 → Home, once, never repeated.
  • Core loop Home 05 → Explore 06 → sheet 07 → mystery 08 → route 09 → arrival 10 → reward 11 → collection 12. Every exit from 11 lands somewhere with a visible gap.
  • Collection branch 12 → 13 → 14 (on completion) → 17 titles; 12 → 15 badge detail; 12 → 16 mystery badge → back to 06 map.
  • Social branch 19 party → 20 quest; 19 → 21 territory → 22 leaderboard; 23 profile → 17 titles, 18 journal, 28 settings.
  • Safety interrupt 26 conditions can be reached from 07 and 09, and escalates to 27 when a checkpoint locks. 27 is reachable at any point in the loop.

Palette

Three independent scales that must never be confused: one accent, one rarity ladder, one safety scale. Rarity is the only thing allowed to use violet, magenta or gold-as-status; safety is the only thing allowed to use green, amber-red or red.

Type

  • Archivo 800–900, tracking −3%: screen titles, badge names, numbers that carry drama. Never below 13px.
  • Instrument Sans 400–600: all sentences. Body copy stays at 13.5px on device, 15px for lead paragraphs.
  • Martian Mono, uppercase, tracking +16%: every piece of game data — serials, distances, XP, rarity, counts, timestamps. This is the HUD voice, and it is what stops the UI reading as a fitness app.
  • The 4 / 7 pattern is always mono, always with the achieved half in ember and the total dimmed. It appears on nine screens and must look identical on all of them.

Motion

  • Badge reveal (screen 11): hexagon scales 0.6 → 1.0 with a 40ms overshoot, rarity glow blooms after, rays rotate behind. Bonus card lands 600ms later so the two rewards read as separate events.
  • Counters XP and collection counts tick rather than swap. 5 / 7 animates the fifth dot filling.
  • Mystery pulse a 2.6s breathing halo on unknown pins and the ??? block. The only ambient loop in the app.
  • Arrival vignette lifts and the scenic saturates over 900ms, then the title sets. No confetti — the place is the reward.
  • All of it respects prefers-reduced-motion; reveals become cross-fades.

Mock data, structured for real APIs

  • Six entities carry every screen: Explorer, Checkpoint, Badge, Collection, Party, Season. Discovery is the join: { explorerId, checkpointId, badgeId, serial, ordinal, claimedAt }.
  • The unknown is a field, not a screen. A checkpoint carries revealState: 'unknown' | 'clued' | 'known' | 'claimed', and every surface renders from that one value. Nothing about mystery is hardcoded per screen.
  • Safety is its own object on the checkpoint — { status, weather, trailStatus, terrain, difficulty, duration, accessibility, access } — so a real NParks or weather feed swaps in behind one interface, and status: 'unavailable' routes to screen 27 from anywhere.
  • Everything is mocked behind a repository layer (lib/data/*.ts) returning promises, so replacing mock with Supabase, Postgres or an internal API touches no component.
  • The bonus roll is a pure function with declared odds in a table, not a random number scattered in the reward component. Odds are printed on screen 11 because that table is the single source of truth.

Decisions I need from you before the build

  • The name. Vantage is a placeholder chosen for the double meaning (vantage point / advantage). Every wordmark, tab label and copy line is a single token away from changing.
  • Target. Next.js in a phone frame (fastest to demo, shareable by link, runs on the hackathon projector) or Expo React Native (real device, real GPS later). The screen designs are identical either way; the component code is not.
  • Map source. The mock map is hand-drawn SVG, which looks deliberate and costs nothing. A real Mapbox style with this palette applied is roughly half a day.
  • Scenic imagery. All hero art here is generated gradients and ridgelines, so there are no licensing issues and no network calls. Real photography would raise the ceiling on screens 01, 10 and 24 specifically.
  • Currency and price points. Shown as S$6.99 / S$49.99. RevenueCat will render the store's real localised price, so these are placeholders for layout only.
